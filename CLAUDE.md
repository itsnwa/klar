# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Klar is a privacy-focused macOS only web browser built with SwiftUI and WebKit. It emphasizes minimal tracking, lightweight performance, and native macOS integration with features like sophisticated sidebar management and command palette.

### Relevant Documentation

Klar is only targeting macOS 26 and upwards, meaning we can use the latest and greatest APIs available on the system. There are some handy documentation for new APIs to use located here:
`/Applications/Xcode.app/Contents/PlugIns/IDEIntelligenceChat.framework/Versions/A/Resources/AdditionalDocumentation`

### Releases

```bash
./ship patch|minor|major   # bump, build, notarize and publish an update
./ship patch --silent      # one that installs on quit without a word
./ship --no-publish        # just the notarized DMG
```

`ship` updates the trackers Klar blocks first (`TrackerBlocker`), then archives with Developer ID signing (Team ID: C4H3XBVK2C, automatic, for the iCloud and passkey entitlements' provisioning profile), packages and notarizes a DMG, and publishes it as the GitHub release `vX.Y.Z` of `itsnwa/klar`, with the DMG and the `appcast.xml` Sparkle's `generate_appcast` makes for it: it commits the bump and pushes main first, and the release is a draft until both files are up. Installed copies read the latest release's feed (`https://github.com/itsnwa/klar/releases/latest/download/appcast.xml`, `SUFeedURL` from `KLAR_UPDATE_FEED`, which only `ship` sets), check at launch and every 4 hours, download by themselves and install with Restart to Update or on quit (`AppUpdater`). Publishing needs the repository public. Klar 1.4.0 and earlier read the old token-gated update server instead, so each release also goes there (`publish_old_server`, `npx wrangler login`) until none are left. The one-time setup is at the top of `ship`.

### Release notes

`Klar/ReleaseNotes.json` is the one source for the What's New page (`ship` also embeds the notes in the appcast, where Klar's update card and palette row take the new version's first feature title from). Keep it up to date as Klar is built:

- When a change people will notice is done (the task is confirmed), add it to the `"unreleased"` entry at the top, in the same commit. Create that entry if there isn't one. Never put a version number on it: `./ship patch|minor|major` labels it with the new version, refuses to publish a new version without notes, and commits the bump (`Klar.xcodeproj/project.pbxproj`, `Klar/ReleaseNotes.json`) once it has shipped. It won't bump while those files have uncommitted changes, so commit work before shipping.
- Pick one list per change. A release can leave out any of them, and they're shown in this order:
  - `new`: a feature worth a headline, as `{ "symbol", "title", "detail" }`. The symbol is an SF Symbol name, the title a few words in sentence case, the detail one sentence about what people can now do.
  - `improvements`: one sentence about something that works better than before.
  - `fixes`: one sentence about what works now, not what was broken. "Set as Default in Settings › General makes Klar your default browser again."
- Write for people browsing with Klar, not for developers. Leave out refactors, tests, build and tooling changes.
- If a later change replaces or undoes an unreleased note, edit that note rather than adding another.
- Debug builds open the unreleased notes from Klar › What's New…, to preview them.
- `./ship patch --silent` (any bump) makes the new version a silent update, when asked for: it adds `"silent": true` to the entry it labels, committed with the bump (don't add it by hand otherwise), marks its section in the feed (`data-klar-silent`, "silent" in its Release notes row), and Klar downloads it without the update card or the palette's row with nothing typed, installs it when it quits, and opens no What's New tab afterwards. Its notes are still in What's New, and in the next announced update's tab.

## Architecture

### Core Patterns

- **Feature-based modules** under `Features/` directory with Views, Components, and ViewModels
- **Manager-based state management** with `@StateObject` and `@ObservableObject` for shared state
- **SwiftUI + Coordinator pattern** for WebKit integration (`TabWebViewCoordinator`)
- **Environment object injection** for cross-component dependencies

### Key Managers

- `BrowserWindowSession`: one browser window's models, and the list of them (statics). Every window shows the same tabs: each has its own pages of them (`TabManager`), selection and expanded folders (`SidebarManager`), active space (`SpaceSelection`), sidebar state (`SidebarStateManager`), find panel, toasts, split views and window chrome (`NativeWindowButtons`, `FloatingSidebarManager`, `ToolbarManager`); the open tabs, saved tabs, folders, pinned sites and spaces are every window's (`OpenTabStore`, `SidebarStore`, `SpaceManager.shared`), as are history, downloads and extensions. The window group presents a session ID (`WindowGroup(id: "main", for: UUID.self)`, SwiftUI's restoration off): `session(forWindowValue:)` gives each window its session, which `KlarApp` hands to `ContentView` and the layout's hosting views as their environment (`browserEnvironment(_:)`). SwiftUI asks for `defaultValue` also when a window opens with a value of its own, and builds a closing window's content once more: `idForNewWindow` makes nothing (a session is made once a window shows it), and a closed session's ID gets that session back (`closedSessions`), never a new one in the list. Each window's values in UserDefaults are its own (`WindowDefaults`: `SavedTabs.<id>`, `ActiveTabId`, `TabMappings`, `ActiveSpaceID`, `LastActiveTabBySpace`, `SidebarVisible`, `SidebarWidth`, `WindowFrame`; the single window's from before were copied to the first session's). `BrowserWindowSessions` lists the sessions to restore, the window last in front first (`all`, reordered on didBecomeKey): `restoreAll()` in `KlarApp.init` makes every session before any window opens (each restores its tabs, so the sidebars' first sync sees every window's), the first window SwiftUI opens takes the backmost, and `openRestoredWindows()` opens the rest once it's up, back to front; each window gets its saved frame as it joins (`attach(to:)`, from `BrowserWindowLayoutView.viewDidMoveToWindow`) and is set up once it's up (`configureWindow()`). `current` is the key browser window's session, else the one last in front (or the one waiting for a window): what menu commands (`BrowserWindow.perform { session in … }`, `BrowserWindow.keySession`), links from other apps (`AppDelegate.handleURL`), Settings and notifications with no tab of their own act on; `owner(ofTab:)` finds the window a tab is in. Closing a window that isn't the last closes its pages (`TabManager.closeAllTabsForWindowClose`: the open tabs stay open, in the other windows; a saved tab open in no window then is unloaded; its private tabs close) and forgets its session; closing the last one keeps its session waiting for the next window (the Dock icon, ⌘N, a link), as with a single window, and quitting keeps them all (`isTerminating`). File › New Window (⌘N) opens a new session (`BrowserWindow.openNew`), Close Window is ⇧⌘W
- Saved tabs in several windows: a saved tab (or pinned site) opens in any window, each window with a page of its own (`SidebarManager.sidebarToBrowserTabMapping`, per window; `isOpenHere`), so selecting it in one window never takes it from another. Its rows, the palette's list and menus show this window's state; `SidebarTab.isUnloaded` says it's open in no window (`SidebarStore.isOpenInAnyWindow`, `isUnloadedAfterClosingHere`). Each page has an ID of its own, never its saved tab's (`SidebarTab.toBrowserTab`): sharing it, a page left open as a regular tab once it was no longer the saved tab's selected the saved tab from its own row; pages saved with one get their own at launch (`TabManager.givePagesTheirOwnIDs`), and an open tab with a saved tab's ID gets pages with other IDs (`OpenTabStore.makePage`). Browser tab IDs are unique across windows. Unloading, ⌘W and the integrity checks act on this window's page; deleting a saved tab, Edit URL and iCloud's changes reach every window's. A saved tab open in a window at quit comes back open there, at the page it was on (`SidebarTabManager.restoreTabs`, from `restoreTabMappings`: the last session's browser tab, suspended until shown; a pinned site's loaded in the background)
- Open tabs (`OpenTabStore`): the regular tabs every window shows, and every Mac while iCloud sync is on, in one list (`OpenTab`: address, title, space, when opened and last used; UserDefaults `OpenTabs`). Each window has a page of its own of each, a `BrowserTab` linked by `openTabID` (saved with the window's tabs), without a web view until it's shown, so selecting one never takes it from another window, as with a saved tab. The store keeps the windows in step (`reconcile`, after any window's tabs or the sidebar structure change): a window's new regular tab becomes an open tab with a page in every other window, in the same order (`pagesWereReordered`, from `TabManager.moveTab`); one closed by hand or by the rules that close tabs closes everywhere (`pageWillClose`, from `TabManager.closeTab`), not one whose window closes; one saved or pinned stops being one (another window's page of it on screen becomes that window's page of the saved tab); a removed saved tab's pages left open become one, with the saved tab's ID, so a Mac where iCloud removes it has its page join the open tab the other Mac made of it rather than add another (`pagesWillBecomeOpenTab`, `formerSavedTabs`). An open tab is where the last of its pages' own navigations went, in any window or on any Mac (`BrowserTab.ownNavigationCount`: a commit, or a new history entry without a load, pushState or back and forward within the page, from `TabWebViewCoordinator`; not a redirect, an address the page rewrote, replaceState, or a load the open tab started, so two windows showing one never send each other back and forth): its other pages follow (`BrowserTab.follow`), one on screen at once, its last page kept in Back, one off screen when it's shown next, its web view let go meanwhile. Where each page last went is the store's (`navigatedAddresses`): a page that only rewrote its address isn't behind. Moving one to another space (`pageDidChangeSpace`) reaches every window, one showing it going along (`SpaceSelection.openTabDidMove`). Not open tabs: private tabs, pages a script opened (`hasOpener`), empty panes and saved tabs' pages. A new window has a page of each and opens the palette for a new tab (`opensWithNewTab`). In iCloud each is an `OpenTab` record, `opentab-<uuid>` (`lastActiveAt` to the half hour, which the rules that close tabs go by); closed ones are remembered for a month (`syncDeletedRecordNames`), so they're deleted from iCloud even when this Mac didn't report them that session, and an earlier copy doesn't reopen them. "When Closing App" closes them everywhere as Klar quits
- Groups (folders in the code, the saved data and iCloud's records: `SidebarFolder`, `folders`, `folder-<uuid>`): a saved group is a `SidebarFolder` (row key `.folder`), drawn as a rounded rect concentric with its row, holding its icon at 14 pt or, without one (`FolderIcons.defaultIcon`), up to 3 of its first tabs' favicons stacked, one per site (`SidebarGroupIcon`, `SidebarGroupIconBox`, `SidebarGroupFavicons`). Open tabs can be in groups too, below the divider: `OpenTab.group` (`OpenTabGroup`: ID, name, icon, on each of its tabs, so it syncs as `groupID`/`groupTitle`/`groupIcon` on the `OpenTab` records; deploy the schema), one level deep, there while it has tabs, its tabs kept together in the open tabs' order (`OpenTabStore.gatherGroups`) and laid out where its first one is (`SidebarLayoutEngine.Input.regularTabGroups`: a `.folder` row, its tabs `.regularTab` at depth 1, the active one `.peekTab` under it closed). Pages not yet open tabs (a link's new tab, a saved tab's page left open) get theirs as they become ones (`pendingGroups`); private tabs and pages a script opened can't be in one (`canGroup`). Moves and group changes go through `OpenTabStore.movePages` / `setGroup` (one change, every window conformed, `.openTabGroupsDidChange`). Dragged between the saved and regular tabs a group keeps its ID, name, icon and open state (`SidebarManager+Groups`: `saveRegularGroup`, `moveSavedGroupToRegularTabs`, which gives a saved tab open in no window an unloaded page, `TabManager.addUnloadedTab`); drop zones below the divider are `.regular(beforeTabID:groupID:dropOnGroupID:)`. The close rules close a group's tabs like any regular tab's (End of Day, When Closing App), but After 24 hours of inactivity goes by the group: its tabs close together once none has been used that long or is on screen (`TabManager.closeInactiveRegularTabs`). ⌘-click selects tabs along with the active one (`SidebarManager.extraSelectedItems`, cleared when `selectedItem` changes); a menu on one of them is for all (`SidebarRowsView.selectedItems(forMenuOn:)`, `SidebarContextMenuFactory.menu(forTabs:)`: New Group with N Tabs, Close N Tabs). With Settings › General › Open links in the tab's group (`[tabs] open_links_in_group`, on by default, synced) a link opened from a tab in a group joins it at its end (`TabManager.createNewTab` → `SidebarManager.groupForLink` / `addLinkTab`): a saved tab in a saved group, which takes its page's address and title once loaded, or an open tab in a group of them
- Moving a tab between windows (`BrowserWindowSession.moveTab`): a tab of a window's own (a private tab, a page a script opened) dropped on another window's sidebar, pinned sites or pages goes there (`SidebarManager.browserTabBroughtHere`; an open tab dropped there is that window's own page of it, and another window's page of a saved tab stays there). Its page goes along as it is: the coordinator is parked (`TabWebViewCoordinator.prepareToChangeWindows`) instead of torn down with the view it leaves (`TabWebView.dismantleNSView` skips one whose tab changed windows or whose web view another container has), and the next window's `TabWebView` adopts it (`adoptAfterChangingWindows`, which points it and its `CustomWKWebView` at the new `TabManager`); one not adopted within 5 s is torn down, its tab suspended. The window it left shows the tab it showed before (`TabManager.detach`)
- `TabManager`: one window's tabs (its pages of the open tabs, its private tabs and pages a script opened, and the saved tabs and pinned sites open in it), the active one, the command palette, split views and toasts; tab lifecycle and navigation. Page notifications with a tab ID are for the window that has the tab, the others for the window in front (`isForThisWindow`): `CreateNewTab` (a `predeterminedTabId` must be made once), `TrackPageVisit` (a private tab's visit seen by another window went into history), `ShowToast`. The command palette's notifications (keys from `KeyboardHandler`, `SetPrefilledURL`, refocus, `ForceTextSelection`, `CommandPaletteSubmit`) are posted with the window's `TabManager` as object, which the palette and its field (`CustomTextField.notificationScope`) observe. A tab closed by hand (`closeTabUndoably`: ⌘W, Close Tab, a row's or the palette's ×) registers Close Tab on the window's undo manager, the Edit menu's: ⌘Z opens a regular or private tab again in a new tab in its place and space, with its back/forward list and zoom (restored as a suspended tab's), and selects a saved tab or pinned site again; ⇧⌘Z closes it again; it goes back into the group it was in (`ClosedTab.group`). The divider above a space's regular tabs, hovered, shows Close All at its right (`SidebarDividerView`, its row covering the spacing around the line), which closes them all, groups' too (`closeTabsUndoably`: one Undo Close Tabs reopens them where they were). Closes by the rules, other windows, iCloud and empty tabs or panes aren't undoable
- `SidebarStore`: the saved structure every window shows (spaces, folders, saved tabs, pinned sites), its persistence and debounced saves, which saved tab each page in any window belongs to (`browserToSidebarTabMapping`; browser tab IDs are unique across windows) and iCloud's sidebar source (`SidebarStore+CloudSync`, which tells each window's `SidebarManager` of removals and new IDs). Each window's `SidebarManager` reads and writes it through `sidebarStructure`, `sidebarStructurePublisher` and `browserToSidebarTabMapping`; every window's sidebar reloads on its changes (a reorder in one shows in all at once)
- `SidebarManager`: one window's sidebar: selection, scroll target, renaming, expanded folders, tab history and each saved tab's page in this window, in step with its `TabManager`; folders, drag-drop
- `SidebarStateManager` (`@Observable`, read with `@Environment(SidebarStateManager.self)`: showing or hiding the sidebar re-runs only the views that read `isVisible`; ContentView reads none of it). The sidebar and the page are laid out by AppKit, not SwiftUI (`BrowserWindowLayoutView`, from `onLayoutChange`): each in its own `NSHostingView` (`SidebarArea`, `BrowserContentArea`; nested hosts don't inherit the environment, so they get the window's models from its `BrowserWindowSession`). The sidebar's frame jumps to where it ends up and a `CASpringAnimation` (additive, on `position.x`) slides its layer there on the render server; the page gets one frame per display-link tick from the same `slideSpring`; out of sight the sidebar is hidden. The page's hosting view doesn't know the window's corners, so `ConcentricRectangle` there gets them as a container shape (`WindowState`, the window's private `_cornerRadius`; full screen leaves out the inset). It holds UI state for sidebar interactions, including the sidebar's zoom `level`: the active space's tabs (`.space`), the overview (`.overview`, `SidebarOverview`: live Downloads / Reading List / History cards and a card per space) or a library list (`.list`, the AppKit list controllers). Pinching the sidebar zooms out and in, following the fingers, and swiping sideways moves between the overview and the spaces, laid out left to right, with the neighboring space shown live (a `SidebarTabsViewController` previewing it); both are `SidebarZoomContent`'s, from `SidebarGestureMonitor`, and only a pinch scales the overview (the button and shortcuts cross-fade). Every level's content starts 16 pt under the URL bar (the overview's first card 8, as the pinned sites do, `PinnedSitesSection.topInset`) and ends 16 pt above the space bar (`SidebarLayoutMetrics.contentEdgeInset`); a hairline separator 6 pt under the pinned sites and above the space bar's buttons (`topSeparatorInset`, `bottomSeparatorInset`; right under a list's header), where the content is cut off, shows while there's more that way (`SidebarScrollView` for the tabs and AppKit lists, `View.sidebarScrollEdgeSeparators()` for SwiftUI's); opening anything from the overview goes back to `.space`, while the lists stay open with the active tab's item selected. The lists share `SidebarLibraryTableView` / `SidebarLibraryRowView` (tab rows' hover and selection: `SidebarTabRowView.hoverFill`, and `selectedFill`, monochrome, a little lighter than hover, with `selectedBorder`, 0.5 pt at half the Now Playing preview's opacity; text keeps its colors) and open pages with `TabManager.openFromLibrary`; an item's context menu comes from `SidebarLibraryMenus`, in the lists and on the overview's cards (`View.libraryContextMenu`, an AppKit menu over the SwiftUI row)
- `SpaceManager` (`.shared`, every window's: the spaces, making, changing and removing them, profiles, data stores, which space a tab is in) and `SpaceSelection` (each window's: its active space, the tab it last showed in each, switching, `move(itemID:toSpace:)`; in the environment, and `tabManager.spaceSelection`): spaces, switched from the bar at the bottom of the sidebar (`SpaceBar`, hosted by `SpaceBarDropView`, which takes tabs dragged onto a space's button and springs that space open when one is held over it; its + opens New Tab, New Private Tab with ⌥ held, New Group, which makes a group in the regular tabs with a new empty tab in it, named first, then the palette for its address, `SidebarManager.newRegularGroupWithNewTab`, and New Space, `showNewMenu`, while a tab dropped on it makes a space). A space is a `SidebarCollection` (icon: its name's first letter or an icomoji; color; separate profile): saved tabs and folders belong to it by `collectionID` (one global `rootItems`; a space's top level is the subsequence in it), regular tabs by `BrowserTab.spaceID`, a saved tab's browser tab by its saved tab (mirrored into `spaceID`). A window's active space follows its active tab; switching shows the space's last tab or the empty state. A new window starts in the space of the window in front. A separate profile is a `WKWebsiteDataStore(forIdentifier: profileID)` (used by `TabWebViewCoordinator.createWebView`, which then skips the pool) and a `HistoryManager.forProfile(profileID)` (stores under `Application Support/Klar/Profiles/<id>/`); moving a tab across profiles reopens it. Settings › Spaces (`SpacesSettingsView`), deep-linked by `SettingsWindowController.showSettings(category: .spaces, spaceID:)`. Icons of spaces and folders come from the icomoji picker (`IcomojiPicker`): an `Icomoji` is an SF Symbol, one of Klar's `brand-…` icons or an emoji, stored as a plain string (the name, or the emoji). The brand icons are Simple Icons' (CC0, some under a license of the brand's own), written by `scripts/update_brand_icons.py` as 16 pt template SVGs, with where each comes from in `docs/brand-icons.md` and, for the app's acknowledgements, the `BrandIconCredits` data asset; brands it doesn't carry, or whose license rules out commercial use, are `CuratedFolderIcons.retiredBrandIcons` (a group that picked one shows its favicons, a space its letter) and `renamedBrandIcons` maps old names. The AI providers' marks in Settings › AI and Find (`AIProvider.iconName`) are their own assets, with the search providers' in `providers/`. Each page is in groups (`IcomojiCategory`: the symbols' and icons' from `CuratedFolderIcons.symbolGroups` / `brandGroups`, `symbolGroups` keeping every symbol a folder could have picked so it stays valid; emoji in Unicode's groups and order from the `EmojiCatalog` data asset, made by `scripts/update_emoji_catalog.py`), laid out as fixed-height rows (`IcomojiGrid`) so the bar of group buttons and the arrow keys know where everything is without measuring; the ones picked last first (`Icomoji.recents`, UserDefaults `IcomojiRecents`), and the search looks through every page
- Pinned sites (`SidebarManager+PinnedSites`, `PinnedSitesView`): the icon grid under the URL bar, shared by every space. It's the space's and the lists' (`SidebarZoomContent`'s overlay; those pages leave room for it, `PinnedSitesSpace`), not the overview's, which has all of the sidebar under the URL bar: a pinch zooms it out and fades it with the tabs, a swipe to or from the overview slides it with the space's page (between spaces it stays), and away it takes no clicks or drops (`PinnedSitesView.isShown`). A pinned site is a saved tab listed in `SidebarStructure.pinnedItems` instead of `rootItems` or a folder, with no `collectionID`: `SpaceManager.spaceID(of:)` is nil for its browser tab, so selecting it doesn't switch spaces and it uses the shared profile, and its tab's `spaceID` follows the active space. Tabs and links dropped on the grid are pinned; moving one into a space's tabs (`moveItemToPosition`) unpins it. A tab row dragged over the grid turns into its tile: the list's view of the dragged row morphs into it (see dragging in a space's tabs, below), as the grid swaps AppKit's image, hidden, for the tile's parts (`PinnedSiteTileView.draggingImageComponents`) and posts `.sidebarItemDragDidEnterPinnedSites`, and back as it leaves (`.sidebarItemDragDidLeavePinnedSites`). A tile's own drag is drawn by the space's list as it draws a row it drags (`SidebarRowsView.beginPinnedSiteDrag`, the list being in the window at every zoom level): it starts out as the tile, and is a tile over any window's grid, a row over a sidebar, a link or a page out of it, giving the selection back as a pressed row does; the grid keeps its slot until the list tells it the drag ended (`pinnedSiteDragDidEnd`), and put back, the tile slides back into it as it opens again (`pinnedSiteDragWillReturn`). Another window's grid it's over lifts its own tile for it out of its slots (`visitingTileID`). Dropped on a grid, the tile starts where the dragged one was. Pinned sites are always loaded (`keepPinnedSitesLoaded`, once launch's sync is done, after any change to the saved tabs or browser tabs), in every window: each keeps a page of its own for each: in the background without autoplaying sound (`BrowserTab.isLoadedInBackground`), never unloaded, and suspended only on critical memory pressure, and ⌘W only leaves one, pausing what plays in it and ending its Picture in Picture (`leavePinnedSite`, `MediaControlManager.pauseMedia`); switching away keeps it playing. In iCloud its tab record's `spaceID` is `pinned`
- Dragging in a space's tabs (`SidebarRowsView`, its own `NSDraggingSource` and destination): the rows make room where a drop lands. The dragged row is lifted out (`SidebarLayoutEngine.Input.hiddenItemID`, a folder with what's in it) and its place stays closed for the whole drag. Drop targets are worked out against that layout without the room made (`dropLayoutRows`), so making room never moves them; the rows from the target down then shift a row, with a dashed slot at its indent (`SidebarDropSlotView`, the pinned sites' too). The regular tabs below New Tab take drops the same way (`DropZone.regular(beforeTabID:)`: over one, before it; past the last, at the end; with none, where the first would be), and dragging one among them reorders them: their order is the window's `TabManager.tabs` (`moveTab(_:before:)`), as is a tab's brought there from a saved tab, another space or window, or a link's new tab. A folder's middle drops into it (lit up, `SidebarFolderRowView.setDropTarget`; held there, it opens), its top and bottom quarters beside it, or before its first child when it's open. The list draws the dragged row itself for the whole drag (`SidebarDraggedRowView`: a row view of its own, configured like the lifted row, opaque in the selected row's color as it shows over the sidebar with its border, `SidebarTabRowView.setDragged` / `draggedFill`, as a pinned tile turned row's drag image is, so a row dropped back in lands in the same color), in a window of its own (`SidebarDragPanel`: click-through, at the dragging level, as big as the screen the pointer is on), so it shows past Klar's window and over other apps; the source's `draggingSession(_:movedTo:)` moves it. AppKit's image is hidden meanwhile: AppKit draws it in a window of its own in this process, not an `NSWindow`, which `SidebarDragImageWindow` finds as the drag first moves (`CGWindowListCopyWindowInfo`, the dragging level) and hides with SkyLight's private `SLSSetWindowAlpha` (a new image, or none, would cross-fade); if it can't be, AppKit's image (a snapshot) is all there is. The row takes the indent a drop would land at on a spring, laid out frame by frame (a display link, the window layout's `SpringValue`), so it narrows smoothly and its title truncates as it goes. Over the pinned sites it turns into the tile it'd be (`.sidebarItemDragDidEnterPinnedSites`, with the tile's size): the row's fill and favicon (`SidebarTabRowView.dragParts`) spring into the tile's (`PinnedSiteTileView.draggedTileColors`), centered under the pointer where the grid lands it, while the title and buttons fade; and back as it leaves. Its shape follows the Klar window under the pointer, its own or another (`BrowserWindowSession.session(atScreenPoint:)`, that window's `layoutView`: `shownSidebarScreenFrame`, `contentScreenFrame`): a row over any window's sidebar, where that window's list makes room and sets its indent (`followDropDepth` reaches the drag's source, `activeDragSource`) and lifts a saved tab or folder dragged over it out of its rows too (`visitingItemID`); a tile over any window's pinned sites (they tell every list, and a dragged tile stays one over another window's grid, `PinnedSitesView.isOverGrid`); a page over any window's pages; a link anywhere else. Dropped in another window, its row comes in from where the dragged row is (the source's grab offset). Out of its own sidebar (its frame on screen, from the source's moves), a tab turns into a link: its fill grows up into an opaque card (the same `draggedFill`) with the top of its page (`WKWebView.takeSnapshot`, from `TabWebViewCoordinator`, taken as the drag starts and again as it leaves; the favicon until there's one), its buttons give way to its address under the title (`SidebarTabRowView.setLinkAddress`). Over a window's pages, where it'd go into a split view, it's the page alone (`.page`): the link's card without the row, which folds away, moved down under the pointer. The shapes (`SidebarDraggedRowView.Shape`: row, tile, link, page) morph into each other the same way (fills cross-fading, premultiplied, so none passes through a lighter or darker one), the row's own fill and favicon hidden while stand-ins in a layer-hosting view under it change. Let go, the row comes in from where the dragged row was: into its slot, or back to its place (AppKit's slide back is off); the list's view of it stays until that layout, or goes at once when something else takes the drop. The drag carries the tab's link too (`NSPasteboardItem.sidebarItem(uuid:link:)`: URL, text, `public.url-name`), so other apps take it (a link in Messages, a link file in Finder); it's a move within Klar and a copy only outside it (`SidebarPasteboardTypes.dragOperations`), so a page doesn't load a tab dropped on it, and Klar's own drop targets go by the sidebar item first
- Arc import (Settings › Import, `ImportSettingsView`, `SidebarImportSheet`): `ArcSidebarReader` reads Arc's `~/Library/Application Support/Arc/StorableSidebar.json` (or a copy chosen from another Mac) loosely, since it's undocumented: spaces with their pinned container's tabs and folders (split views flattened, notes and easels left out), icon (emoji, else an SF Symbol of the same name, else the letter), color (nearest `SpaceColor` to the theme's mid tone) and profile, and every profile's favorites, into an `ImportedSidebar` (the model shared by every browser Klar imports from, `SidebarImportSource`). `SidebarManager.importSidebar` merges it in one save: into the Klar space of the same name or a new one (a separate, empty profile for an Arc space on a non-default profile), folders matched by name, tabs already in the same place and favorites already pinned left out, so importing again adds only what's new. Favorites become pinned sites. Today's tabs, history, passwords and website data aren't imported; Arc's extensions are, from Settings › Import or Extensions (`ExtensionImportSheet`)

### Logging System

Uses performance-optimized centralized logging (`Logger.swift`):

- Categories: `.sidebar`, `.tabManagement`, `.webView`, `.media`, `.persistence`, `.dragDrop`, `.general`, `.history`
- Levels: `.verbose`, `.debug`, `.info`, `.warning`, `.error`, `.off`

- Release builds: `.error` only, in the system log (`log show --predicate 'subsystem == "com.itsnwa.browser"'`), and nothing from a private tab's page: an error raised for a page passes `isPrivate:` (the tab's `isPrivate`, or `webView.isPrivateBrowsing` where only the web view is at hand), which release builds leave out

- Debug runs from Xcode show only Klar's own log messages (and runtime issues, `com.apple.runtime-issues`): `scripts/debug-log-filter/KlarDebugLogFilter.c` interposes `os_log_create`, handing every other subsystem a disabled handle, and drops messages without a subsystem (`OS_LOG_DEFAULT`: what WebKit forwards from its page processes, `WebContent[pid] …`) as they're sent (`_os_log_impl` and friends, and `os_log_pack_send`, which Swift's `os_log` uses). The "Debug log filter" script phase builds it for Debug only, outside the app bundle, signed as the app, and the scheme loads it (`DYLD_INSERT_LIBRARIES`). The system's and WebKit's messages are still in the system log of a Release build (`log stream`, Console). Don't use `OS_ACTIVITY_MODE=disable`, which silences Klar's logs and the runtime issues too

### Swift 6 and concurrency

Swift 6 language mode, with the main actor as default isolation (`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`) and approachable concurrency (`SWIFT_APPROACHABLE_CONCURRENCY`): everything is `@MainActor` unless marked otherwise, and a `nonisolated` async function runs on its caller's actor.

- What runs off the main thread is `nonisolated`: types used on a queue of their own (`HistoryStore`, `SQLiteDatabase`, `PasswordManager`, `NativeMessagingConnection`, `SRPSession`, `CRXFile`, `CloudSyncStore`, `SSLBypassManager`, a `Mutex`), plain data that's encoded, ranked or searched in the background (sidebar and space models, search results, split geometry), and the `Logger`. Extensions of a nonisolated type need `nonisolated` too
- Async work that should stay off the main thread is `@concurrent` (`ExtensionInstaller`'s package checks); a `nonisolated` async function alone runs on the main actor when called from it
- Observers for the main queue: `NotificationCenter.addMainObserver(forName:object:using:)` (its block is the main actor's). Timers' blocks, `NSAnimationContext` completions and AppKit's `queue: nil` notifications are `@Sendable` and run on main: their bodies are in `MainActor.assumeIsolated`
- WebKit's delegate handlers are `@MainActor` (`completionHandler: @escaping @MainActor (…) -> Void`): without it, a method only nearly matches the protocol (a warning) and WebKit never calls it
- A closure written in main-actor code and run elsewhere by an API that doesn't take a `@Sendable` one (a `DispatchSource` handler on another queue, an `NSImage` drawing handler) is the main actor's, and traps there: mark it `@Sendable`
- `isolated deinit` where a main-actor class's deinit touches its state

## WebKit Integration

The app uses a sophisticated WebKit integration pattern:

- `TabWebViewCoordinator` manages WebView lifecycle and delegates
- `CustomWKUIDelegate` handles web navigation policies
- `WebViewPool` for performance optimization
- Tabs restored at launch or resumed from suspension get their web view lazily and don't autoplay sound (`TabWebViewCoordinator.createWebView`; `mediaTypesRequiringUserActionForPlayback = [.audio]`, so muted background videos still play)
- As a web view widens (the sidebar closing, the window growing), the page lays out for the new width a frame or two later; until then the strip past its edge shows the page's extracted color (`WKWebView.setUndrawnAreaColor`, the private `_setBackgroundColor:`), instead of WebKit's dark default. `drawsBackground` off would make pages without a background transparent, and `underPageBackgroundColor` doesn't reach that strip
- All web views share one WebKit process pool (`WebViewConfiguration.useSharedProcessPool`): each pool lists every installed font on the main thread before its first page (~40 ms), which a pool per configuration paid on every new tab
- Web developer tools (Settings › General › Web Developers, `[general] web_developer_tools`, each Mac's own, off by default; always on in Debug builds, which leave the setting alone since they share config.toml): `WebViewConfiguration.showsDeveloperTools` turns on developer extras (Inspect Element in the page's menu) and `isInspectable` (Safari's Develop menu) for every web view, and store extensions' `isInspectable`; changing it reaches open tabs (`TabWebViewCoordinator.setDeveloperTools`, a tab with its inspector open left as is), the pool and extensions at once. Off, developer extras are on for a web view only once ⌥⌘I opens its inspector (`enableDeveloperTools(for:)`): while they're on, WebKit's console agent keeps a page's last ~100 console messages, arguments included
- A background tab's web view is out of the window (`WebViewContainerView.setActive`), so WebKit lets its rendered layers be reclaimed, throttles the page and suspends its process 4 minutes later, unless `TabWebViewCoordinator.keepsWebViewInWindow` (docked inspector, playing media, camera/microphone). Sheets and popups for a page use `webView.presentationWindow`, which also finds the window of a background tab
- The Now Playing preview in the sidebar (`NowPlayingWidget`) is live, for the window's own tabs: the background tab's own web view is lent to it (`WebViewContainerView.lendWebView(to:)` / `reclaimWebView`), kept at its size and cropped/scaled to the video's rect (polled from the page once a second), with the page's pointer events off. The web view itself isn't drawn there, but stays in the window and not hidden: for a hidden page, WebKit's GPU process takes down the video's layer (`AudioVideoRendererAVFObjC::destroyLayer`). Instead, the preview hosts the video's render context again: a private `CALayerHost` copying WebKit's host layer for the video, found in the web view's layer tree and looked up again once a second, since WebKit replaces it when the page is hidden and shown. Without one, the web view shows. To scale smoothly, the crop is rasterized and mipmapped down. That pass runs on every video frame, and over the whole web view it cost WindowServer ~4× the GPU time. Showing the tab, hiding the sidebar or dropping the tab's web view takes it back. No frames are copied out of the page. A button over the preview on hover pops the video out to Picture in Picture (`MediaControlManager.enterPictureInPicture`, from `evaluateJavaScript`, which counts as a user gesture); while it's there, the preview gives way to the row alone
- A crashed web process (`TabWebViewCoordinator.webViewWebContentProcessDidTerminate`): a background tab is suspended (reloads when shown), the active one reloads once, and a second crash within 30 s shows the "This Page Keeps Crashing" error page. WebKit's own reload, without that delegate method, looped on pages that crash on every load
- Microsoft work and school sign-in on a Mac managed with Intune (`MicrosoftEntraSSO`, called from both navigation delegates): a top-level navigation to Microsoft's sign-in hosts is cancelled and loaded again with the headers the Company Portal's Enterprise SSO plug-in hands out (`ASAuthorizationSingleSignOnProvider`, operation `get_sso_cookies`), which prove the device to Conditional Access. Only while the plug-in is set up (`canPerformAuthorization`); not for non-persistent data stores or frames. The plug-in only answers browsers on Microsoft's own Team ID list, which Klar (C4H3XBVK2C) isn't on, so it declines ("the teamId … is not allowed", logged as an error) and isn't asked again that launch. What does work is WebKit's own Extensible SSO (on by default in every WKWebView), once the company's admin adds `com.itsnwa.browser` to the plug-in's `AppAllowList` in its MDM profile
- Keys the page didn't handle stop at `CustomWKWebView` (it takes the place of WebKit's `_web_superKeyDown:`) instead of going up the responder chain to a beep: a ⌘ shortcut has been through the menus by then (WebKit sends it again once the page passes on it). Only Escape goes on, in WebKit's full-screen window, which exits on it. Keyboard focus belongs to the active page: `TabManager.focusActiveWebView()` when the window opens and when the command palette or find panel closes. Nothing in the SwiftUI tree should be `.focusable()` around it
- Klar's shortcuts are the browser windows' alone (`BrowserWindow`: SwiftUI's `main` windows, no sheet over one), each acting on its own window: `KeyboardHandler` (one for the app) finds the session of the window a key was typed in (`BrowserWindowSession.session(for:)`), and leaves keys typed in any other window (Settings, popups, extension windows and popovers, the Web Inspector, sheets, alerts, panels, a page in full screen) to it, and the mouse's back/forward buttons go back and forward only over a browser window, in it. The menu's commands look at the key window: Close Tab closes another window (`performClose`), Find goes up its responder chain (`findInKeyWindow`), zoom does nothing there, and the rest (tabs, spaces, the palette) bring the browser window in front forward first and act on its session (`BrowserWindow.perform`), not while a sheet is over it. WebKit's own full-screen window counts as the browser's for the menu (`isKey`)

### Performance Best Practices

#### Mouse Event Handling

- **Avoid global mouse tracking** - Use targeted hover handlers instead of `acceptsMouseMovedEvents`
- **Conditional state updates** - Always check `if state != newValue` before updating to prevent unnecessary redraws
- **Pre-calculate geometry** - Cache complex calculations outside of hover handlers
- **Minimize tracking areas** - Only use `.mouseMoved` when absolutely necessary

#### Hover State Management

```swift
// ✅ Good - conditional update
.onHover { hovering in
    if isHovering != hovering {
        isHovering = hovering
    }
}

// ❌ Bad - always updates
.onHover { hovering in
    isHovering = hovering
}
```

#### Liquid Glass

- Glass follows its place in the window: a glass view that moves, such as with the sidebar sliding in or out, is worked out again on every frame, even when it's transparent. Only keep it in the hierarchy while it shows (`if` plus a transition, `glassEffectTransition(.identity)`), not hidden with opacity
- The command palette, the Find panel, the loading bar and toasts are `spaceGlass(in:)` (`SpaceGlass`): regular glass tinted with the active space's color to match the window's frame (`SpaceTint`), dark in dark mode (a near-black tint, since glass has no dark style) and milky in light. The split view's pane controls (`NSGlassEffectView`) take the same tint resolved for their appearance (`SpaceGlassTint.nsColor`). Glass draws what it's applied to on top of itself: put it on the content or on `Color.clear` behind it, never on a filled shape, whose fill (the foreground color) covers the glass. Content on glass is drawn vibrant, so a `.primary` fill turns light gray on light glass: use a fixed color

#### Animation Optimization

- **Debounce frequent animations** - Avoid triggering multiple simultaneous animations
- **Use shorter durations** for hover effects (0.15s or less)
- **Conditional animation triggers** - Only animate when state actually changes
